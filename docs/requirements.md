# Unself 自托管协作平台需求清单

> 状态：架构决策 v2（2026-09-06）
> 背景：Unself 做的是自托管团队协作。平台两条路：安装器只把 core 和 workbench 部署到 Cloudflare，或者用 Docker 拉起 workbench。模块另装。文里出现的 unself.cn、Stalwart 和 Gitea 都是团队自己的参考部署，不是产品强制要依赖的东西。
>
> 产品不是 SaaS。装一次，就是部署者自己的独立实例，Unself 不承载中央租户、用户数据或者组织配置。
>
> 这份文件只写「要什么」。产品定位看 docs/product.md；架构契约看 docs/architecture.md；现状和约束看 docs/product.md「现状与约束」。拍板写进对应文档的正文，过程留在 issue 和 PR。

## 1. 身份与成员体系（P0）

- [x] **登录**：内置账号（用户名+密码）是默认的；也可以接标准 OIDC（Issuer、Client ID、scope 和 claim 映射；Stalwart、Keycloak、Authentik、Zitadel 这类兼容提供方都行），SSO 按钮跟着实例配置决定显不显示。
- [x] 用户主键是 `issuer + sub`（每个实例一个独立库，`instance_id` 冗余，所以不落列），邮箱只用来显示和发通知，不能拿它当不可变的身份主键。（2026-09-23 对齐：`0001_init.sql` `UNIQUE(issuer, sub)`）
- [ ] 团队角色分管理员 / 用户 / 访客；管理员只管当前这套实例对应的一个团队，模块权限由实例配置和模块自己的策略一起定。
- [x] 成员加入只有一条路：邀请链接；已经有 OIDC 账号的人首次登录会自动 JIT 建档，直接复用。（2026-09-13 对齐）
- [x] 模块身份：模块碰不到外部 OIDC，只认核心签发的模块 token（JWT、aud=模块、10 分钟、静默续期、postMessage 握手交付）；模块后端只管验签。（2026-09-23 对齐：#217 模块 JWT 验签落地；`core/sdk` client 10 分钟静默续期）
- [x] 模块 token 里的 sub 是核心内部的稳定用户 id；`issuer + sub` 的映射只存在核心。（2026-09-23 对齐：签发只写 sub=内部 uid）
- [ ] 成员一停用就立刻广播踢人事件，token 短时效只是兜底上限；登出由壳清掉会话再广播，外部身份源的 SLO 先缓一缓。
- [x] 第一个管理员靠一次性 setup token 产生，用完立刻失效，这条路直接封死。（2026-09-23 对齐：#165 加固 + `one_time_tokens` 迁移）
- [ ] 邮箱开户、密码管理、应用专用密码和离职停用都走可选的 Provisioning 适配器；支持 Stalwart API、SCIM 或 Webhook，但这些不是 OIDC 的职责。

入门的门型与身份-邮件组合按下表定案。

### 门型

| 门 | 形态 | 状态 |
|---|---|---|
| 一次性+限期邀请链接 | 一条链接一个人，默认 7 天有效（1-365 可调） | 现状 |
| 批量门（限次+限时） | 一条链接 N 人、短时窗 | 扩展位，有真实需求再开 |
| 永久链接 | 常开共享密钥 = 变相开放注册 | 不做 |
| 开放注册 | 无门直接申请 | 不做 |

### 注册矩阵（身份轴 × 邮件轴）

| 实例配置 | 批准时发生什么 | 用户设几次密码 | 登录怎么走 |
|---|---|---|---|
| 内置·无邮件（最小形态） | 翻状态 pending→active | 一次（注册时） | Unself 密码表单 |
| 内置+邮件 | Stalwart 开户 + 后台尽力发信（激活走邀请页自助） | 两次：登录密码（注册时）+ 邮箱密码（邀请页自助设置） | Unself 密码表单 |
| Stalwart 兼任 IdP+邮件 | Stalwart 开户（账号既是邮箱也是 IdP 账号）+ 后台尽力发信 | 一次（邀请页激活时设的密码既是邮箱密码也是登录密码） | 跳转 Stalwart OIDC |
| 独立 IdP（Keycloak 等）+无邮件 | 只翻状态，不开户 | 零次（IdP 侧账号团队自建；Unself 不做通用 IdP 开户） | 跳转 IdP |

## 2. 邮件（可选适配器）

- [x] 本团队这套 Stalwart 参考部署有 SMTP、IMAP、DNS 和外发基础设施。
- [x] 平台上的邮件能力 = 运行时邮件配置（/admin/settings mail 段）+ SMTP 发信和 Stalwart 开户适配器；撑起入职激活（开户 + 激活链接）和通知邮件；邮件模板只做三个 render——`account_ready` / `invite_result` / `module_toggled`（`core/adapters/mail-smtp/src/templates.ts`），站内通知另外有 `invite_pending`，**没有独立的欢迎信**；Git 事件投递放到 M3。（2026-09-15 对齐）
- [ ] Stalwart 适配器支持可选的开户、禁用、应用密码和限速管理。
- [x] 没配邮件的时候，平台照样能跑，通知默认走站内通知。（2026-09-23 对齐：M1 最小版（弱化形态）实机验收通过，见 issue #22）
- [ ] 邮局和 OIDC Provider 可以是同一个服务，也可以完全分开。

## 3. Git 集成（可选模块）

- [ ] 支持 Gitea、GitHub、GitLab Webhook 的签名校验，事件格式统一。
- [ ] 聊天模块开着的时候，事件能进「Git 动态」频道；邮件模块开着时，能发邮件通知。
- [ ] 本团队 Gitea 参考配置：审批注册、`@unself.cn` 邮件规则和 Stalwart SMTP。
- [ ] Git 服务不该成为核心登录或工作台可用性的单点依赖。

## 4. 可选协作模块（P1-P2）

每个模块都得能单独启用、禁用、部署和升级。模块没启用，就不能出现在统一壳的边栏里，也不能要求为它建专属云资源。

模块是自包含的 npm 包。壳和模块之间只走 manifest、`@unself/sdk` 和 Core API。模块内部怎么实现，壳不管。地址不写在清单里。

### 4.1 聊天（可选）
- [x] 聊天模块就是 `app/modules/chat`（包名 `@unself/chat`）。代码源自 EdgeChat，现在是本仓库里的一个模块，不是还要再接的外部产品。（2026-09-23 对齐：`@unself/chat` 0.1.1 已发 npm）
- [x] 频道消息、附件、消息持久化已经在这个模块里（表：`channels`、`messages`、`message_attachments`、`uploaded_files`）。
- [ ] @ 提醒和历史检索还没单独立项验收。
- [x] 逐条已读回执在聊天模块里（`read_receipts`）。（2026-09-23 对齐：#220 落地，#239 终验）
- [x] 通过核心签发的模块 token 接入（模块碰不到外部 OIDC），不依赖原来那套本地账号体系。（2026-09-23 修正表述：#217）

### 4.2 日历（可选）
- [ ] 个人日程、共享日程和会议邀请。
- [ ] 通过 CalDAV/JMAP/iCalendar 适配器接入；Stalwart 是参考实现之一。
- [ ] 自建响应式日历前端，能与标准 CalDAV 客户端互通。

### 4.3 会议（可选）
- [ ] 默认官方实现：Cloudflare Worker + Durable Object 负责鉴权、房间状态和 WebSocket 信令。
- [ ] 浏览器用 WebRTC 建 P2P 音视频和屏幕共享，媒体不经过 Worker。
- [ ] 可以配外部 STUN/TURN；SFU、录制和大规模会议交给 Docker/外部服务扩展。
- [ ] 参会者音频在浏览器本地录；音频存档永不上云，可以手动导出，也不备份。
- [ ] 转写分两档：普通会走云转写（Web Speech），机密会由主持人强制完全本地（量化 Whisper）或者干脆不转；成员可以 opt-out，各自转自己那条音轨。
- [ ] 时间轴用会议 DO 的房间时钟：入场领偏移、本地自己打时间戳、散场只传纯文字片段，Worker 负责排序合并。
- [ ] 合并后的记录参会者可读、主持人独占写；个人片段参会者互相可见；没启用文档模块时，记录留在会议模块里。
- [ ] 配了 AI Provider 之后，经 SDK AI 能力（ai.complete()）生成摘要、行动项和纪要；文档模块开着时经核心代调（act claim）写进文档，参会者天然可读、主持人可写（按核心通用 ACL 记）。
- [ ] 录音、转写和 AI 处理开始前明确提示；管理员能按实例策略关掉云转写通道。

### 4.4 文档与看板（可选）
- [ ] Markdown 文档协作、评论和基础权限。
- [ ] 看板视图管任务，任务截止日期可以同步到已配置的日历。
- [ ] 不需要重型多维表格引擎。

### 4.5 文件、通知与日报（可选）
- [ ] 文件走 core 的 S3，或走模块自己 env 里的存储。不另做一层存储适配器。
- [x] 站内通知是基础能力；邮件通知要等邮件轴（/admin/settings mail 段）开了才可用；服务端发信是后台尽力而为，失败了不阻塞审批。
- [ ] 日报/周报、评论和简单统计放到后面的模块。

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 产品形态 | 自托管软件，一次部署对应一个独立实例；非中心化 SaaS |
| 首选部署 | 安装器把 core 和 workbench 部署到使用者自己的 Cloudflare 账户。模块不在这一步装 |
| 替代与扩展 | Docker 拉起 workbench；模块也可以自己用 Docker 跑。TURN/SFU/录制仍是可选外部组件 |
| 访问入口 | 每个实例使用自己的域名和 HTTPS |
| 身份 | 通用 OIDC；Stalwart、Keycloak、Authentik 等均可接入 |
| 模块 | 左侧导航由启用模块动态生成，模块可独立升级和停用 |
| 移动端 | 平台级要求：一切界面 mobile 可用（能看+轻操作）；审批=桌面管理页主入口+手机同页响应式。工作台壳双形态（桌面左栏/窄屏底部标签栏）；PWA 安装化在 M6 |
| 数据备份 | 部署者负责关键数据备份；官方提供 R2/S3/NAS 等示例 |
| 权限 | 管理员 / 用户 / 访客，另加模块级权限 |
| 视频会议 | P2P WebRTC 优先；Worker 只做信令；TURN/SFU 为可选外部扩展 |
| 文件存储 | core 的 S3，或模块 env 里自己的存储 |
| 可维护性 | 平台和模块分开装、分开升级；许可证边界按包分开 |
