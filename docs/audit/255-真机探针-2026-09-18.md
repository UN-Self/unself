## 探针方式（可用性说明）

复用仓库**真实 REST 原语**（`RestClient` / `putWorker` / `RestD1ControlPlane`），不另写一套：

1. 用装配器同参数的 esbuild 构建**真 chat 模块** `modules/chat/worker/src/index.js` → `app.js`（1,004,573 B）；
2. **先部署 stub**（`export default { fetch() { return new Response('stub') } }`，行状即线上那 298 B 占位脚本）；
3. **再部署真 chat 模块**：
   - 旧判定路径（不带 `migrations`）→ 复现失效；
   - 新判定路径（带 `migrations v1`）→ DO 类建立、模块可访问；
4. 真机 D1 上直测 `markMigrationApplied` / `appliedMigrations`（#248 同一套记账表）；
5. 实测「重复 tag」契约（记账漏写时必然发生的那种重发）。

> 偏差声明：探针走 **workers.dev 脚本端点 + CF API**，未创建 zone 路由 / DNS 记录，故 `probe-255.handywote.top` 未实际使用；隔离靠资源命名 `unself-probe-255-*` + 独立 workers.dev 脚本。完整九步装配（含 zone 路由）不走本探针——九步内部装配路径的判定由 `deploy/cloudflare/test/chat-steps.test.ts` 的行为用例覆盖。
