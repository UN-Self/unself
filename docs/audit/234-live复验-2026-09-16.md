## B. 实时面不通过（新开 #235）

### B.1 探针：store 收到的是 **字符串**，不是已解析帧

在页面内包裹 `store.receiveRoomFrame` 记录实参类型（收到 `read_receipts` / `message` 帧时）：

```text
234-a __rfType: [{"typeof":"string","head":"{\"protocolVersion\":1,\"type\":\"read_receipts\",\"room\":{\"id\":1,\"kind\":\"pub"}]
234-b __rfType: [{"typeof":"string","head":"{\"protocolVersion\":1,\"type\":\"read_receipts\",\"room\":{\"id\":1,\"kind\":\"pub"}]
```

`receiveRoomFrame` 按对象判型（`frame.type === 'ready' | 'message' | 'read_receipts'`），字符串恒 undefined → 分支全落空、静默返回（无异常无日志）。
根因：`modules/chat/frontend/src/lib/api.ts:162` `socket.addEventListener('message', (event) => handlers.onMessage(event.data))` 未 `JSON.parse`；
mock 实现自己解析（`mock-api.ts:390`），单测直接传对象 → CI 全绿掩盖 live 缺陷。

### B.2 同刻「UI vs API」对照（甲侧，未重开房间）

```text
UI （18:07 screenshot 234-01）: msg1..3 = 已读 1/2、msg4 = 未读、msg5 = 无回执标签
API（18:08）                   : msg1..4 = 2/2、     msg5 = 1/2（readBy 只有乙/丙）
```

乙在 general 发消息（msg7）后，甲侧 DOM 尾部仍无该消息；甲重开 general（历史补拉）后才出现 `bubble-theirs`。

### B.3 正对照：只差一个解析（解析补丁 → 实时链立即恢复）

浏览器内（**不落代码**）把 store 方法包一层 `typeof f === 'string' ? JSON.parse(f) : f` 后：

```text
# 乙发 msg8 → 甲侧不重开房间即实时渲染：
[{"t":"bubble-theirs","text":"#234 正对照：乙发（甲实时收帧，需解析补丁）","receipt":null}]
# 甲 WS 入帧序列（探针）：
in  {"type":"message","message":{"id":8,...}}                       ← 实时消息到达并被处理
in  {"type":"read_receipts","messageId":7,"userId":1,...}
in  {"type":"message","message":{"id":9,...}}                       ← 甲自己的回显
in  {"type":"read_receipts","messageId":9,"userId":8,...}           ← 乙读 → 甲侧实时回执
# 甲侧 state.readReceipts 出现 msg9 的回执：{"9":{"count":1,"readBy":[{"userId":8,...}],"total":...}}
```

### B.4 次生问题：解析修好后暴露的自消息竞态（实测丢气泡）

同一次正对照中，甲发送 msg9 后：

```text
甲 state.messages: [1,2,3,4,5,7,8]        ← 缺 msg9
乙 state.messages: [..., "5:走查甲", "7:走查乙", "9:走查甲"]   ← 乙侧正常
甲 state.readReceipts["9"] = count1(乙)   ← 甲侧收到 msg9 回执，却没有 msg9 气泡
```

成因：WS 回显分支只 `rememberMessage(message)`（标记已消费、不入列），而 REST 回包走 `if (result.created) handleMessage(...)`；
回显先到 → REST 分支被 `seenMessageIds` 去重挡回 → 自己的消息不上屏。
另（观察项）：`openRoom` 关旧 socket 后，旧 socket 的 `close` 事件仍把 `state.realtimeStatus` 置为 `closed`（新 socket 已 open；实测该状态下实时帧仍在到达）。

→ 上述两点已写入 [#235](https://github.com/UN-Self/unself/issues/235) 的「次生问题」节。

## E. 临时脚本（不入库；复现用）

### E.1 `/tmp/234-probe2.js`（浏览器 init script：WS 帧与 store 入参探针）

```js
// SPDX-License-Identifier: AGPL-3.0-only
// #234 复验临时探针（不入库）：
// ① 包裹 window.WebSocket，记录 URL/入帧/close（window.__wsProbe）
// ② store 就绪后包裹 store.receiveRoomFrame，记录每次帧处理时的 myUserId/messages（window.__rframe）
(() => {
  const Orig = window.WebSocket;
  window.__wsProbe = { sockets: [], frames: [], closes: [] };
  function Wrapped(url, protocols) {
    const ws = protocols === undefined ? new Orig(url) : new Orig(url, protocols);
    const key = String(url).slice(0, 100);
    window.__wsProbe.sockets.push(key);
    ws.addEventListener('open', () => window.__wsProbe.frames.push({ dir: 'open', key }));
    ws.addEventListener('message', (e) => window.__wsProbe.frames.push({ dir: 'in', key, data: String(e.data).slice(0, 400) }));
    ws.addEventListener('close', (e) => window.__wsProbe.closes.push({ key, code: e.code, reason: e.reason }));
    ws.addEventListener('error', () => window.__wsProbe.frames.push({ dir: 'error', key }));
    return ws;
  }
  Wrapped.prototype = Orig.prototype;
  for (const k of ['CONNECTING', 'OPEN', 'CLOSING', 'CLOSED']) Wrapped[k] = Orig[k];
  window.WebSocket = Wrapped;

  window.__rframe = [];
  const patcher = setInterval(() => {
    const app = document.querySelector('#app')?.__vue_app__;
    const s = app?._instance?.setupState;
    if (s?.store && !s.store.__rframePatched) {
      const orig = s.store.receiveRoomFrame;
      s.store.receiveRoomFrame = function (f) {
        window.__rframe.push({
          t: f && f.type,
          mid: f && f.message && f.message.id,
          my: s.store.state.myUserId,
          ids: s.store.state.messages.map((m) => m.id),
        });
        return orig.call(s.store, f);
      };
      s.store.__rframePatched = true;
      clearInterval(patcher);
    }
  }, 100);
})();
```
