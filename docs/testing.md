# 测试标准（用户拍板 2026-09-08，波次 0.5 成文）

## 拍板原话（真值记录）

> 集成测试为主，少量单测。测试主要依靠 fake factory，测试的时候可以使用 sqlite 模拟 D1 行为，而且测试应该是真实的业务行为以及边界行为，不是现在这种看似"全绿"但是实际上还是一堆问题。测试主要是来描述预期效果的。

> 测的方法函数业务逻辑是不是我们预期的那样工作，而不是判断某些代码在不在，前端是不是有这个文字。……一改代码测试也得跟着改有什么意义？

## 两问检验（每个测试写完必问）

1. **故意改坏业务行为，它会红吗？**——不会红的测试是装饰品，删。
2. **重构实现但行为不变，它要改吗？**——要跟着改的测试是在测实现不是测行为，是负资产，删。

## 怎么写

- **后端**：路由级集成（`app.fetch` / `app.request`）为主；纯函数单测只给真正的纯逻辑（签名、解析、校验）。
- **替身只出现在外部边界**：D1 → 真 SQLite 加载真 migrations（范本 `services/core-api/test/test-factory.ts`，node:sqlite 零依赖）；IdP/时间/随机 → fake。业务代码内部不打桩。
- **前端**：断言用户可见行为（点击后路由变化、请求发出、状态切换），不断言 DOM 结构、类名、文案存在。
- **边界行为必须测**：并发、TOCTOU、格式变体、空态、失败态。每个 bug 修复配一正一负。
- **跨版本升级要测**：迁移改动必须用「**老库（旧迁移已应用）+ 新迁移**」跑一遍，不能只测「全新库重放全部迁移」——后者会把「按文件名记账、旧文件原地改不重跑」的问题全遮掉（实例见 AGENTS.md 已知坑）。

## 禁项

- 断言「代码在不在」：文件存在、路由数组包含子串、内部调用计数
- 断言「页面有这段文字」：模板子串、快照测试。边界：**状态切换后的可见结果**（如操作成功/失败的提示文案）允许断言；恒定静态文案与源码子串禁止。（2026-09-13 对 #138 评审 T1 补口径）
- 恒真 / 自证循环：测试断言自己的 fixture
- 手搓假 D1（无 schema 概念，SQL 错了照样绿——#56 幻影列即此溜过）

## 职责边界

- 视觉与动线走查由**主会话**用浏览器（agent-browser）执行，单测不替代肉眼；worker 在 PR 里标注待走查项，不自行跳过。
- 纯重构 PR：旧测试零改动通过，这是「测行为不测实现」的直接推论。

## 开工前边界自查（8 项，每个 issue 开工前逐条自问自答）

写第一行代码之前过一遍这 8 问，答案写进 issue 评论或 PR 描述（`.github/PULL_REQUEST_TEMPLATE.md` 已落成打勾表）。答不上来 = 还没想清楚，先想清楚再动手：

1. **并发**：同一请求并发打进来（双击/重放/双标签）会怎样？重复开户？重复扣费？——靠数据库约束（UNIQUE/PK）硬闸还是应用层软闸？
2. **TOCTOU**：检查与落库之间有窗口吗（先查后写，中间能插队）？软闸挡不住的那一列，硬闸在哪里兜底？
3. **空态**：列表为空、字段为 null、刚部署没数据时，用户看到的是合理提示还是报错/白屏？
4. **失败态**：下游（IdP/邮件/存储）挂了、超时、返回垃圾时，用户看到什么？会留孤儿数据吗？回滚吗？
5. **大小写**：标识/邮箱/用户名的大小写变体（`A@x.com` vs `a@x.com`、`Alice` vs `alice`）算同一个人吗？存储归一了吗？唯一约束是大小写敏感的吗（`lower()` 索引）？
6. **唯一性**：重复提交同一表单会插两行吗？约束在 schema 还是只在提交时点校验？
7. **明文落库**：密码/token/密钥有没有明文进库、进日志、进错误消息？一次性令牌只存哈希了吗？
8. **权限保真**：前端藏起来的入口/按钮，直接打 API 能打通吗？服务端有没有独立再验（权限只信服务端会话）？

## 取证留档规则（X1：验收取证必须有原件）

背景：M1 验收「取证」无原件（现场数据当天清零，不可回放）——文字转述不是证据。

规则：

- **涉及生产/真实环境核验的查询与输出必须落文件**：SQL 命令原文 + 原始输出（含行数、时间戳），存进仓库 `docs/audit/`（随 PR 提交）或当次 issue 指定的持久路径；不留只在终端/聊天里。
- **落档的取证文件不列入 /tmp 清理**：/tmp 只放可再生的临时物；取证原件不可再生（现场已变），清理脚本与人工清理都必须跳过它们。
- 文件名建议：`docs/audit/<issue 号>-<主题>-<日期>.md`（如 `docs/audit/190-b9-唯一性预检-2026-09-15.md`）。
- 只读查询优先；确需写操作的取证，先留档查询计划再执行。
