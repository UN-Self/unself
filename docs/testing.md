# 测试标准（用户拍板 2026-09-08，波次 0.5 成文）

## 拍板原话（真值记录）

> 集成测试为主，少量单测。测试主要依靠 fake factory，测试的时候可以使用 sqlite 模拟 D1 行为，而且测试应该是真实的业务行为以及边界行为，不是现在这种看似"全绿"但是实际上还是一堆问题。测试主要是来描述预期效果的。

> 测的方法函数业务逻辑是不是我们预期的那样工作，而不是判断某些代码在不在，前端是不是有这个文字。……一改代码测试也得跟着改有什么意义？

## 两问检验（每个测试写完必问）

1. **故意改坏业务行为，它会红吗？**——不会红的测试是装饰品，删。
2. **重构实现但行为不变，它要改吗？**——要跟着改的测试是在测实现不是测行为，是负资产，删。

## 怎么写

- **后端**：路由级集成（`app.fetch` / `app.request`）为主；纯函数单测只给真正的纯逻辑（签名、解析、校验）。
- **替身只出现在外部边界**：D1 → 真 SQLite 加载真 migrations（范本 `services/core-api/test/test-factory.ts`，node:sqlite 零依赖）；IdP/时间/随机 → fake。业务代码内部不打桩。
- **前端**：断言用户可见行为（点击后路由变化、请求发出、状态切换），不断言 DOM 结构、类名、文案存在。
- **边界行为必须测**：并发、TOCTOU、格式变体、空态、失败态。每个 bug 修复配一正一负。

## 禁项

- 断言「代码在不在」：文件存在、路由数组包含子串、内部调用计数
- 断言「页面有这段文字」：模板子串、快照测试
- 恒真 / 自证循环：测试断言自己的 fixture
- 手搓假 D1（无 schema 概念，SQL 错了照样绿——#56 幻影列即此溜过）

## 职责边界

- 视觉与动线走查由**主会话**用浏览器（agent-browser）执行，单测不替代肉眼；worker 在 PR 里标注待走查项，不自行跳过。
- 纯重构 PR：旧测试零改动通过，这是「测行为不测实现」的直接推论。
